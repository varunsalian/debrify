Debrify · Profiles · feature access

Four questions, not a switch wall

Feature access becomes a short questionnaire at profile creation (re-runnable from Edit): identity first, then four human questions. The role choice IS the preset — picking Kid pre-answers every following step, so the common path is confirm-confirm-confirm-save. Changing any answer just diverges from the preset. The v1 features hide behind four human questions; the raw switches survive only inside a collapsed Fine-tune drawer. Two things are deliberately NOT questions: catalog search (typing a title and getting posters from the profile's own catalogs is always there), and the admin's curation of any profile's sources — which addons and torrent engines a profile has is set by you on the Review screen, independent of what the profile may touch itself.

Rules of the design

Preset = prefilled, never locked

  • Role picks answers; it never removes questions. Every household with a "kid who gets YouTube" is one tap on step 3.
  • Divergence is fine and unceremonious — no "custom profile" mode, no warning. The preset is a starting point, not a contract.
  • Admin/Member paths breeze: all steps arrive pre-answered ON, so creation is four Next taps.

Off means invisible — and enforced

  • A disabled feature drops every road to it: nav tab, Home rows, settings-search entries, deep links, and remote commands that would open it.
  • UI hiding is the courtesy; the operation boundary (ProfileFeature checks) remains the actual guarantee, per the threat model.
  • Page gates are NOT content safety — the rating ceiling stays its own future feature and gets a line on the Kid card when it exists.

Search is two things

  • Catalog search — type a title, the profile's catalogs answer with posters. Always available to every role; it is how anyone finds anything.
  • Keyword search — raw release strings from torrent engines. The only search that is a permission.
  • What makes catalog search safe for a Kid is not a toggle — it is the SOURCE LIST the admin curated.

The admin curates every profile's sources

  • Which addons, torrent engines and shared connections a profile has is assigned per profile by the admin (Review → "Edit sources", and Edit Profile later) — the existing resource-grant machinery (stremioAddon, jackett, prowlarr resource types) wearing a human UI.
  • "Manage own sources" only decides whether the PROFILE may edit that roster too. Off for Maya ≠ Maya has no addons — it means only you shape theirs.
  • Every profile starts with EVERYTHING enabled — addons, debrid & cloud, engines — except TRACKERS, which default off: watch history is personal, and a shared Trakt/Simkl would interleave two people's scrobbles. Sharing a tracker stays possible, one tick, for the household that wants it.

Scope & adaptation

  • v1 = these ten (pages, actions, Manage own sources, and Cloud files — Admin-only by preset); Backup & transfer remains the fast-follow.
  • TV: identical four steps; cards become the DPAD rows Debrify already speaks. One question per screen is remote-friendly by construction.
  • Editing later opens the Review frame directly — chips first, "Re-run questions" and Fine-tune beneath.
