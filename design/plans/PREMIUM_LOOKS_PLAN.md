Successor to `AWESOME_LOOK_PLAN.md` (phase three, shipped

## 0 · The thesis, and the test

The twenty shipped themes were ported from a mockup that rendered twenty
palettes on one identical layout — so they ARE palettes. A user reads
silhouette before colour: where the edges are, how things are lit, how the
cursor behaves, what waiting looks like. Today none of that varies.

**The acceptance test for the whole programme:** a screen recording with the
colours removed must still look different per theme. Silhouette, light,
motion — and on Android TV with sound on, it must *sound* different too.

## 1 · Ground rules

1. **Legacy is byte-identical at default platform settings**, every new token
   a pinned no-op. Standing exception: reduced motion.
2. **Signal cannot be deleted** — `AppThemes.legacy.core` IS Signal. It
   leaves the picker, not the registry.
3. **Surface and ink migrate together, both directions.**
4. **Every TV policy is a method on the token**, gated on
   `PlatformUtil.isTelevision`. The full platform contract is §2a. **[R2]**
5. **A token nothing consumes is decorative** — every §3 token names its §5
   sweep or is explicitly carried/stretch.
6. **One derivation module owns all token derivation** (main session only);
   never build `ThemeData` in `build()`; hoist scope reads; `InheritedTheme`
   for anything dialogs keep; publish-first prefs; pins composed as the
   source composes them.
7. Feature branch **`premium_looks`** off `tvos_port`, rebased weekly.
8. Per-phase gate: analyze 0 errors · theme suite green · legacy goldens
   unchanged · Codex review.
9. **Every week ends shippable-inert.**

## 3 · The vocabulary

New groups on `AppTheme`, derived in the one owning module, memoized, no-op
under legacy.

### 3.1 `SurfaceTokens` — separation, family-aware **[R2]**
Round 2 was right that one `model` field cannot express "space on cards,
rule in settings". The contract is **`modelFor(SurfaceFamily)`**: the spec
declares a base model plus per-family overrides, and the resolver clamps each
family to its legal set —

- families: `card`, `shelfRow`, `hero`, `sheet`, `dialog`, `settingsGroup`;
- caps: `settingsGroup` ∈ {fill, rule}; `sheet`/`dialog` ∈ {fill, glass};
  `card`/`shelfRow`/`hero` ∈ all four.
- models: **fill** (legacy pin, all families) · **glass** · **space** · **rule**.

Glass is delivered through a shared **`GlassSurface`** widget owning both
filter and opaque fallback: **8 live non-player `BackdropFilter` sites**
adopt it (round 2 confirmed the 8/4 split; the other grep hits are
comments), the one site with no TV bypass gains one, four player sites
excluded. `glassFor(isTv)` returns the opaque recipe — a stated property.
Plus `sheen` and `elevationRamp` (rest/raised/floating through
`shadowFor(isTv)`).

### 3.2 `LightTokens`
`scrim`: **bottomGradient** (legacy pin) · **blurBand** (via `GlassSurface`)
· **plate** · **fullDim** — at the bounded text-over-artwork sites.
`vignette` · `focusBloom` (0 on TV) · `washes` (generalising the existing
trio).

### 3.3 `ArtTokens`
`frame`: **contained** (legacy) · **bleed** · **matted** · **faded**.
`grade` per D5. `reactiveRoom` (0..1) on the existing `tvHeroTint` wire.
**Inventory first**: ~80 image-constructor sites across ~41 non-player files
(round 2's count) walked into a frame/grade-eligibility list before any
conversion; the shape sweep's `brImg` sites are a seed, not a classification.

### 3.4 `FocusTokens`
`expression`: **ring** (legacy) · **scale** · **lift** · **invert** ·
**flood** · **underline** — consumed in the focus chokepoints. The 2.5px TV
floor and `focusOn` rescue stand.

### 3.5 `MotionTokens`
`character`: **standard** (legacy) · **snap** · **glide** · **settle**,
through the existing `AppMotion` resolver; `entrance` (none/fadeUp/stagger)
folded in. Reduced-motion and TV-zero rules stand.

### 3.6 `SoundTokens` + haptics — with causal attribution **[R2]**
Round 2 killed the naive design: a `FocusManager` listener alone ticks on
dialog autofocus, route entry, `requestFocus` restoration (≈776 call sites),
IME and pointer focus. The dispatcher therefore requires **causal evidence**:

- a root key listener mints a one-shot token **only for directional
  `KeyDownEvent`/`KeyRepeatEvent`** — key-up never mints, and select/back
  never mint (so a select that pushes a route cannot authorise the new
  route's autofocus tick). A focus change emits a tick only by consuming a
  token younger than ~100 ms, and **each token is consumed by at most one
  focus change**; programmatic focus finds no token and stays silent; **[R3]**
- select/back sounds are explicit calls at the existing activation
  chokepoints, never inferred from focus;
- held-DPAD repeats DO mint tokens (each repeat is a real traversal), so the
  ~60 ms rate limiter is the stated defence against repeat-series spam —
  by design, not by accident; **[R3]**
- muted whenever `AppSurfaceState.active` is frozen.

Tests: held-DPAD spam, dialog open/close silence, route-autofocus silence,
programmatic-restore silence, select on every activation path, frozen mute.

### 3.7 `IdleTokens` — with the transition table **[R2]**
`policy`: **none** (legacy) · **dimChrome** · **theater**. TV only in v1.

| Event | Behaviour |
| --- | --- |
| Input (any key/pointer) | `idleDim` animates to 0; timer restarts from zero (never resumes elapsed) |
| Aggregate trailer-active rises | `idleDim` forced 0; timer suspended (idle never arms during a trailer) |
| Aggregate trailer-active falls | timer restarts from zero |
| Surface freezes (player, splash) | `idleDim` forced 0; timer suspended |
| Surface unfreezes | timer restarts from zero if trailer-active is false; stays suspended if true **[R3]** |
| Producer disposal | each producer resets only its OWN notifier — the compositor owns nothing |
| Effective dim | `max(trailerDim, idleDim)`, computed once in the shell |

### 3.8 `WaitTokens`
`skeleton`: **shimmer** (legacy) · **pulse** · **static** · **scanlines**.
One widget family.

### 3.9 `DensityTokens` — seam 2, stretch **[R2]**
Four metrics, each pinned to today's literal under legacy and bounded:
`rowHeight` ±20% · `cardScale` ±15% · `pageGutter` ±25% · `sectionGap` ±30%.
Consumed at the shelf/grid chokepoints only. **Stretch-scheduled** (§9): the
seam is designed now so it cannot be improvised later, built only if the
weeks run clean — and it is first on the cut list either way.

### Cut from v1

bypass it — v2 with that inventory as entry ticket) · splash continuity ·
picker previews · ink ratchet (protects light themes, which are v2 — D1) ·
metadata grammar · personalized accent · scheduled looks · per-profile

## 4 · Authoring: `ThemeSpec`

~12 decisions (ground, ink, accent, material, light, artwork, focus, motion,
sound, density, idle, type pairing); one derivation feeds `AppTheme
.fromDetail` — spec → complete `DetailTheme` core → `fromDetail` →
subprofiles + groups, one owning module, no duplicated authority. Meaning
roles (`state`, `callout`, `calloutText`, `focus`, button inks, washes) are
required inputs or derived by `fromDetail`'s reviewed rules — never silently
defaulted; optional-with-neutral applies only to texture-class dimensions.
Legacy and Signal never route through the spec.

**Spec snapshots [R2]:** every non-legacy look pins what its decisions
derived to. During W2–W5 the five exist as *provisional* specs whose
snapshot updates are ordinary reviewed diffs; the **shipped baseline freezes
at W6 device signoff**, not before — iteration and snapshots don't conflict,
they sequence.

## 12 · W1 inventory findings (read-only, complete) **[W1]**

Three parallel read-only agents walked the tree. Every count the plan guessed
was right; the *conclusions* drawn from several were not.

### Glass — 8 non-player + 4 player, confirmed

* **`poster_play_loading_overlay.dart:106` — the one site with no TV bypass —
  is DEAD CODE.** `PosterPlayLoadingOverlay.show` has zero callers anywhere in
  `lib/`. The sub-task is a **delete**, not a fix.
* `mobile_floating_nav`'s three sites also lack a bypass but are unreachable
  on TV by construction (mobile shell only); `GlassSurface` gives them one for
  free.
* **`GlassSurface` needs a `sigma` parameter**, not a constant: the Torbox
  dialog helper is one invocation with four call sites at σ12 and σ8.
* The three player `_frost` helpers are byte-identical triplicates — a free
  dedupe if glass ever crosses that line, but D7 says it does not.

### Surface families — the caps were right, with one new guard

| family | owner(s) | space-safe? |
| --- | --- | --- |
| card | `CatalogItemTile`, `PlaylistGridCard/LandscapeCard` | **yes** — focus border is a `Positioned.fill` *inside* the clip, so it never insets |
| shelfRow | `CloudFileRow`, `SourceRow`, `TorrentResultRow` | **yes, with a guard** — Cloud/Source hold border width constant and vary only colour; **`TorrentResultRow` varies `borderWidth` on focus and must be pinned to a constant width first** |
| hero | `_HeroSpotlight`, `HeroTrailerBackdrop`, `TvAmbientArtStage` | **yes** — already effectively `space`; every layer is a gradient |
| sheet | `_NeonActionSheet` + two inline panels | no (capped) — the fill *is* the modal |
| dialog | `DialogThemeData` + ~30 hand-rolled panels | no (capped) |
| settingsGroup | `SettingsSection` | **no** — rows have *zero* inter-row gap and an in-place `Border.all`; removing both shifts every row 1px AND dissolves the grouping. Confirms the §3.1 cap. |

**Two chokepoint gaps to plan around:** there is **no shared sheet builder**
(53 raw `showModalBottomSheet` across ~30 files; nearest seam is the
`sheetSurface` token) and **no dialog owner** (236 `showDialog`, 137
`AlertDialog`; only seam is `DialogThemeData`). `modelFor(sheet|dialog)` is
therefore enforceable *through those two seams plus a named list*, not
universally — so those families ship `fill` in v1 and glass only where the
shared widget is adopted.

### Artwork — 80 sites / 41 files, exactly as estimated

29 poster · 17 backdrop · 12 still · 14 logo · 8 chrome. **41 of them sit in
scrolling lists** — that is the fling-risk set. **24 are hero/single-image**,
which is precisely the degraded scope D5 falls back to.

* **Zero `colorBlendMode` uses exist today** — there is no prior grade to
  preserve, so the token starts clean.
* **`stremio_tv_tuner.dart:1247-1261` already contains D5's answer.** It ships
  a `ColorFiltered` on the non-TV path and *explicitly refuses it on TV*, with
  the saveLayer cost written into the comment. That is the precedent to cite
  and the exact shape `gradeFor(isTv)` should take.
* **Three constructors serve two buckets each** (`_ArtPoster`, `_LogoChip`,
  premium `_Poster`) — they switch role on a `BoxFit`/caller flag. A grade
  keyed on the *site* mis-applies on all three; they need a **parameter**.
* **Five of the eight "chrome" sites are cast headshots.** Faces grade very
  differently from title art — they need their own opt-out, not the chrome
  default.
* `lib/screens/video_player_screen.dart` is a **top-level file**, so it is not
  covered by the `lib/screens/video_player/` exclusion. One site; exclude it
  by name.

### Focus and sound — the root listener is feasible, and already precedented

* **`HardwareKeyboard.instance.addHandler` is the mechanism**, and this repo
  already runs one: `main.dart:1130` (`_tvDeadFocusRecovery`) sees every key
  *before* the focus tree, already discriminates `KeyDownEvent` and the arrow
  keys, and returns `false` to leave events untouched. The token minter is
  ~40 lines beside it — **one file, zero call-site churn**.
* **`TvOverlayBack` (`tv_keys.dart:43-56`) is an existing one-shot
  `mark()`/`consume()` token** — the DPAD token is its direct structural
  sibling, not a new idea.
* The consumer half is also precedented: `search_screen.dart:1422` already
  runs `FocusManager.instance.addListener`.
* **The minter must NOT be TV-gated.** The existing handler is installed only
  under `_isAndroidTv`; desktop keyboard users generate real traversal too.
* **`focusInDirection` bypasses key events entirely** — 74 sites, including
  the phone remote (`remote_command_router.dart:1204`) and `main.dart:3140`.
  Those mint nothing and stay silent. If the phone remote should click, that
  is **1–2 explicit mints**, not N.
* **`dialog_tap_guard.dart` exists because DPAD select fires BOTH a KeyDown
  and a synthetic tap on Android TV.** A naive "emit on `onTap`" scheme would
  double-fire against an "emit on `isActivateKey`" scheme on the same press —
  select must be emitted at exactly one of the two.
* Counts confirmed: **776 `requestFocus` sites**, ~202 autofocus-capable
  sites. Select collapses to **~8 shared helpers**, not the 200 raw
  `isActivateKey` call sites.
* **`DetailFocusRing` (`detail_style.dart:137`) is the only fully
  token-driven ring in the app** — it already reads `focusWidthFor`,
  `focusOffset` and `focusOn`. It is the model `FocusTokens.expression` should
  generalise, not a new invention. Note three *different* focus-detection
  mechanisms are in use (`onFocusChange`, `node.addListener`, `hasFocus`
  polling), so the expression token must not assume one.

### Net effect on the plan

No P0. Three scope reductions (dead-code delete, sheet/dialog ship `fill`,
faces opt out of grading), two additions (`GlassSurface` sigma param,
`TorrentResultRow` width pin), and one meaningful de-risk: the sound
attribution design has a working in-repo precedent for both halves.

## 13 · What has actually landed **[W2–W5, uncommitted]**

Written from the tree, not from the schedule. Nothing here is committed.

### The five looks are live, not staged

The W2 review's first P1 was that they could not be selected at all. Fixed at
the level that matters: **`AppThemeController._recomputeSilently` — the method
the running app reads — now resolves a premium id through
`ThemeSpec.buildWith(core)`.** `AppThemes.byId` doing it was not enough;
that method is not on the live path. The core still goes through
`AppThemeAdapter.resolveCoreText` first, so a premium look follows the
text-brightness preset like every other theme.

Registered in `kDetailThemes`, `kDetailThemesShipped`, `DetailThemes.premium`
and `DetailThemes.catalogue` (premium first, which is picker order). The 20
old cores are untouched and `DetailThemes.all` is still `const` and still 20 —
the cull removes them, this does not.

Codex reviewed the tree afterwards and found four P0s. Three were real and are
fixed (blur and pane opacity lost under Classic at ten sheets; a suppressed
transparent border still insetting content by a phantom pixel; `ThemedSkeleton`
calling `repeat()` before its controller had a duration, which threw on the
first frame of any animated wait style). The fourth — `TorrentResultRow`
losing its inset because `DecoratedBox` does not apply `BoxDecoration.padding`
— was a real bug in my own fix and is now a `Container` again, with the reason
written above it.

### Deliberate gaps

- **Density has no consumer.** It is the plan's stretch item and first on the
  cut list, and the §12 sweep found no chokepoint a mechanical adoption could
  take safely — the four metrics live in a dozen widgets' literals. Adopting
  it at one skeleton would have made it decorative, which is the failure the
  W2 review already caught twice.
- **The cull has not run.** §8 is written and the acceptance sets are staged,
  but deleting the 19 is gated on W6 device signoff (§9), and the five looks
  have not been seen on a real panel yet. Deleting the fallback in the same
  change that introduces its replacement is the one ordering the plan
  explicitly forbids.
- **`AppScrim` found no adoptable site.** Every hand-rolled gradient outside
  the detail layouts turned out to be a shell wash, a placeholder fill or
  player chrome over the trailer's punched video hole — not text-over-artwork.
  The scrim grammar reaches the screen through `DetailScrim` instead. The
  widget stays for the sites a future layout will have.
- **Three spike verdicts still need hardware**: Mi Box audio latency, the
  30-poster grading fling benchmark, and the tvOS release-build no-op check.
  `ThemedArtwork.gradeInLists` is the kill switch for the second.

### One structural fix worth naming

`TorrentResultRow` drew a border whose WIDTH changed with state (1 / 1.5 / 2),
and `Container` insets its child by the border it draws — so the decoration
was in the layout path, and a `space` look dropping it would have reflowed the
row. The border is now split: a transparent border of the same width holds the
inset, and the visible ring is a `Positioned.fill` sibling. Same pixels, same
focus wobble, and `shelfRow` can now legally take `space`.

### Known legacy deviations, named rather than discovered

The byte-identity rule allows exactly one exception (reduced motion). These
are the places this wave came close, and what was done about each.

1. **Blur under Classic — fixed, and it was nearly a P0.** `SurfaceTokens
   .legacy` is `fill`, so a naive "blur only under a glass look" rule would
   have deleted a real `BackdropFilter` from ten phone sheets the moment they
   adopted `GlassSurface`. `SurfaceTokens.isNeutral` now distinguishes *stated
   fill* from *no opinion*: a look that says `fill` has chosen not to blur; a
   look that says nothing has not, and the site's shipped `sigma` survives.
   `adoption_legacy_test.dart` pins it for Classic and for all twenty cores.
2. **The blurred tint — fixed.** Every converted site shipped its fill as a
   ternary (opaque on TV where the blur was skipped, translucent elsewhere).
   Collapsing it to one colour would have made the phone sheets opaque. The
   widget now takes both as `tint` and `blurTint`.
3. **The four Torbox dialogs were REVERTED, not accepted.** Their old
   `_maybeBlur` wrapped the whole `Dialog` rect *unclipped*, so the blur was
   visible in the 16 px margin around the panel; `GlassSurface` always clips,
   and the two cannot both be true. I first wrote this down as an accepted
   deviation. That was wrong — the invariant permits exactly one exception and
   this is not it — so the file is back to what it shipped, byte for byte.
   `GlassSurface`'s doc now names the shape it cannot express: a filter that
   wraps a margin-bearing or full-screen widget rather than the panel itself.
   The nav barrier is the same shape and stays raw for the same reason.
4. **`TorrentResultRow`'s ring animates as its own layer.** Split from the
   container so the decoration leaves the layout path; both halves tween on
   the same 200 ms curve, so the border still moves as one thing.
6. **The idle timer suspends on the trailer's chrome dim, not on an aggregate
   frame signal.** There is no aggregate — `MainPageBridge.tvChromeDim` is
   what the shell itself already uses to hide the rail, so the compositor
   reads the same thing. A trailer that plays without dimming chrome could
   still let the timer arm; that needs a real trailer-active aggregate, which
   is its own change.
7. **`EntranceStyle.stagger` currently renders as `fadeUp`.** One live caller,
   and it is a single card, so there is no sequence to stagger. A missing
   consumer rather than a broken token: it upgrades for free when the home
   board's sections adopt `HomeSectionReveal` and pass their positions.
8. **`invert` and `flood` degrade to a ring unless the call site supplies
   `inverted`.** By design — the widget paints behind its child, so over an
   opaque card neither would be visible at all, and only the caller knows
   which of its children are ink. Today `TvFocusableButton` opts in; the other
   four fall back to a cursor that always works.
5. **The five focus widgets keep their shipped ring under Classic and hand
   the cursor to the theme otherwise.** Forced, not chosen: `FocusTokens
   .legacy` is width 2.5 and every one of those sites ships 1.5, 2 or 3, and
   `FocusExpressionBox` exposes no width override. Gating the whole wrap on
   `isLegacy` is the only way to say "keep the shipped width" from a call
   site.
