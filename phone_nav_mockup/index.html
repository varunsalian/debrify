Phone Nav — Classic, four ways

The community ask: "a proper classic nav system for Android." Today phones navigate through the floating glass button — every switch is two taps + a hunt through an overlay, the current tab is never glanceable, and no muscle memory can form. These concepts replace it with a persistent bottom bar, each solving the same hard problem a different way: Debrify has 10–11 phone destinations and a classic bar holds five.

Real phone inventory (integration-gated per user): Main Home · Discover · Downloads · Calendar†  |  Browse IPTV · YouTube  |  TV Debrify TV · Stremio TV  |  Library Cloud  |  Setup Addons · Settings.  †Calendar only when Trakt/Simkl is connected; Downloads/Cloud/Debrify TV only with a debrid configured — the bar must survive items appearing and disappearing.

Recommendation — ship C2 (it is C1 with one extra sheet)

C1 is the correct skeleton — a real Material bottom bar, labels on, active state always visible, one-handed. But any fixed five is wrong for someone: no-debrid users have no Cloud, Trakt users live in Calendar, IPTV-first users never touch Discover.

C2 fixes exactly that with machinery Debrify already believes in — per-user nav is house DNA (integrations can already hide from nav; Calendar appears only when connected). Defaults = C1; long-press or Edit in the More sheet to swap slots 2–4. Ezrik gets his classic bar on day one and never has to know the edit exists.

Rollout safety: the floating glass button stays as a Settings choice ("Navigation style: Classic bar / Floating button"), classic default on phones. TV sidebar and desktop rail untouched. One caveat for the build: tab indices are load-bearing (switchTab(n) sites project-wide) — the bar must map by index table, never by position.
